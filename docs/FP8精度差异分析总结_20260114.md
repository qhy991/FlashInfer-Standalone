# FP8 精度差异分析总结

## 日期
2026-01-14

## 关键发现

### 不同的 CUDA Runtime

| 组件 | CUDA 版本 | FP8 实现 |
|------|-----------|----------|
| **PyTorch** | 12.8 (内置) | PyTorch 内置 `.to(float8_e4m3fn)` |
| **FlashInfer** | 12.8 (来自 PyTorch) | 同 PyTorch |
| **Standalone** | 12.2 (系统) | 自定义 `float_to_fp8_e4m3_host()` |

```bash
# 验证
$ python3 -c "import torch; print(f'PyTorch: {torch.__version__}'); print(f'CUDA: {torch.version.cuda}')"
PyTorch: 2.9.1+cu128
CUDA: 12.8  # ← PyTorch 自带的 CUDA 12.8！

$ ls /usr/local/cuda
/usr/local/cuda -> /etc/alternatives/cuda
/usr/local/cuda-12 -> /etc/alternatives/cuda-12
/usr/local/cuda-12.2  # ← 系统只有 CUDA 12.2
```

## 问题回答

### Q: 为什么 FlashInfer 可以使用正确的 FP8 转换，而 Standalone 不行？

**A**: 它们使用不同的 CUDA runtime！

```
FlashInfer 执行路径:
Python → FlashInfer → PyTorch API → PyTorch bundled CUDA 12.8 runtime
                                         ↓
                                    正确的 FP8 转换 ✓

Standalone 执行路径:
C++ → nvcc (CUDA 12.2) → 编译链接到系统 CUDA 12.2 runtime
                                    ↓
                                有 bug 的 FP8 转换 ❌
```

### Q: 两者不都在 CUDA 12.2 下执行吗？

**A**: **不是！**

- **FlashInfer**: 实际运行时使用的是 PyTorch 自带的 CUDA 12.8 runtime
- **Standalone**: 使用的是系统安装的 CUDA 12.2 runtime

### Q: 为什么不能使用相同的转换函数？

**A**: 技术限制：

1. **编译时绑定**: Standalone 用 `nvcc` (CUDA 12.2) 编译，链接到 CUDA 12.2 的库
2. **运行时绑定**: 运行时动态加载系统 CUDA 12.2 的 `libcudart.so`
3. **PyTorch 隔离**: PyTorch 的 CUDA 12.8 runtime 不会暴露给外部程序

```cpp
// Standalone C++ 代码
#include <cuda_fp8.h>

// 这调用的是 CUDA 12.2 的内置转换（有 bug）
__nv_fp8_e4m3 fp8 = __float2_fp8(value);

// 无法直接调用 PyTorch 的 FP8 转换！
```
